# 回归对照：微调 + 三批新规则，在没人调过的文档上退了什么（2026-09-21）

**结论：没有成片的倒退。** 48 份从没被任何规则或训练材料看过的文档上，该遮的值从"露出 213 处"降到"露出 86 处"，
多遮从 161 处降到 100 处，两个方向同时变好。真正变差的只有 **13 处**，其中 4 处是空格和破折号（不算泄露），
剩下 9 处集中在**一个可以复现的类型**：地址块里单独成行的城市名。

数据集：`benchmark/regression/`（30 份新消费者文档 + 18 份"讲东西不讲人"的文档），做法和冻结声明见它的 README。
对照的两套配置：

| | 引擎 | 模型 |
|---|---|---|
| before | `65e73e2`（微调前，2026-09-21 的 ID 规则 / 跨度补全 / 公司规则都还没有） | 原版 `xlmr_ner_hrl` |
| after | 工作区当前状态 | `xlmr_ner_docudis`（ft4） |

## 真正变差的 13 处

先去掉 4 处记分假象——它们只是把一个值拆成两段遮，中间的空格或破折号没遮，没有任何信息露出来：
`Declan O Riordain`（签名行，露一个空格）、`Puente Almanzor`（同）、`12 rue des Tanneurs — ZA du Ried`（露 `— `）、
以及 `London` 在页脚那一次（另一次露出来，见下）。

剩下 9 处，**7 处是同一件事**：多行地址块里，城市单独占一行时整行没被遮。

```
en-bank-01，当前配置（· = 遮住）
·····························
Personal Lending Services
···········
Leicester          ← 街道遮了、邮编遮了、城市这一行原样留着
········

Mrs ·····················
·······················
·················
Bristol            ← 收件人自己的地址，同样
·······
```

| 文档 | 露出来的 | before |
|---|---|---|
| en-bank-01 | `Leicester`、`Bristol` | 都遮住 |
| en-insurance-01 | `London`、`Road`（换行后单独成行的街道尾巴） | 都遮住 |
| en-lease-01 | `Manchester` | 遮住 |
| en-letter-01 | `Rotherham` | 遮住 |
| es-lease-01 | `Avinguda del`（散文里换行截断的街名） | 遮住 |

另外 2 处是散文里的地名，和 3.5e 的 B 组是同一类判断，不是新问题：
`fr-cv-01` 的 `Italie`（`nord de l'Italie`）、`fr-policy-01` 的 `Île-de-France`（只遮住了 `de-France`）。

**为什么冻结集上看不见**：冻结的 60 份里，多行地址块基本都是"街道 / 邮编 + 城市同一行"的排法，城市单独成行的只有
个位数，而且大多挨着一个被遮住的跨度，跨度补全顺手吃掉了。这批新文档里英式信头写成了四到五行，城市自成一行，
补全规则"吃到第一个散文词为止"够不到上一行，模型又不再单独认它——两者都没接住。

## 多遮：总量降了，但新增 46 处

新增里三类值得管：

| 类 | 例子 | 来源 |
|---|---|---|
| 说明书里的产品号、零件号被当成编号遮掉 | `HX-440-S`、`88-4401-S`、`41-2400-B`、`TH-VLT-4200-B`、`VLT42-KJ-01873` | `regex:universal:labeled_id` |
| 通告里的街名被遮，通告就没法读了 | `on Carlow Street`、`la calle Herradores`、`le boulevard Sainte-Colombe`、`de la avenida de los Olmares` | 模型 |
| 标签词和职级被当成实体 | `SIRET`（3 份法语文档里被标成 ADDRESS）、`IBAN`（标成 PERSON）、`Grupo 3` / `Grupo 4`（标成 COMPANY） | 模型 + `regex:es:company_head` |

`IBAN` 被当人名这条，和 3.5f 里真机上的 `en-contact-01` 是同一个，现在桌面上也复现了。

## 建议

1. ~~**地址块里单独成行的城市**是唯一该修的~~ —— **已修，见下一节**。
2. 说明书的产品号（`universal:labeled_id` 吃掉 `HX-440-S` 这类）要收紧：这批只有 6 处，但受害的是"用户贴一页
   说明书"的场景，遮了就看不懂了。
3. 散文里的地名（`Italie`、`Île-de-France`、通告里的街名）两边各有一半：现在既漏了一些又多遮了一些，
   说明模型对它的判断本来就不稳。这仍是 3.5e B 组那个等你拍板的口径问题，定了再动。
4. `SIRET` / `IBAN` / `Grupo N` 这类标签词被当实体，单独看都不严重，但它们说明 ft4 在"全大写短词"上还有噪声；
   如果以后再训一轮，这是现成的训练信号。

## 修复：地址块里没被遮住的整行（2026-09-21）

`packages/docudis_engine/lib/src/repair.dart` 的 `_addressBlockLines`，补洞的第 4 条规则：
**上一行和下一行都是"地址行"、中间这一行本身只由地址词构成时，这一行单独成为一个地址区间。**

- "地址行"的判定是 **这行印出来的东西有六成已作为地址遮住**，不是"行里有个地名"。第一版写成后者，
  简历里的职务行被吃掉了（`Severnside Logistics Ltd, Avonmouth` / `Transport Supervisor` /
  `- Plan daily routes covering Bristol, Bath and Weston-super-Mare`——上下都带地名，中间那行就成了夹心）。
  收紧后消费者集上这处多遮消失，回归集上修好的 6 处一处没丢。
- 一次最多取两行：城市，加上换行截断的街道尾巴（`…, Nether Parkfield` / `Road` / `Sheffield`）。
- 每行各成一个区间，**不把旧区间撑过换行**，信头排版不变。
- 行里已经有任何检测（包括默认不遮的日期、金额）就不碰：地址行之间的一个日期不是地址。
- 职务 / 部门词（`titleStoplist`）出现在这一行就不碰。

结果：

| | 上线配置 | + 本次修复 |
|---|---|---|
| 回归集：露出来的值 | 86 | **81** |
| 回归集：多遮（A / B 组） | 30 / 70 | 30 / 70（**没涨**） |
| 消费者集：零可识别泄露文档 | 36 / 60 = 60% | **40 / 60 = 67%** |
| 消费者集：泄露率 / 多遮 | 4.8% / 90 | **4.3%** / 90 |
| 公开集 / 合成集 / 手写集 | — | 逐实体**零变化** |
| 反例集误报 | 1（`C. Domicilio`） | 1（同一处） |

消费者集那 7 处提升是同一个形状：`Bristol`、`Co. Galway`、`Ecclesall`、`Sheffield`、`Leeds` ×2、`Loughborough`，
全是信头里单独成行的城市——冻结集上它一直在漏，只是没人按"整行"去看过。

引擎测试 407 个全过（新增 6 个：夹心生效、换行街道尾巴、公司名下的商号行不吃、日期行不吃、正文不吃、简历职务行不吃）。
回归集上剩下的 `es-lease-01` 的 `Avinguda del` 不在此列：那是散文里换行截断的街名，上一行不是地址行，本规则够不着。
